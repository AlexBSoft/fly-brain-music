# Dr. Stun — мир глазами мухи

Браузерный аудиовизуализатор: дрозофила смотрит клип в трёхмерной сцене, а нейрокарта художественно откликается на звук и изображение. Локальный файл пользователя остаётся в его браузере. Музыкальная библиотека и плейлисты хранятся на сервере в отдельном томе.

## Запуск для разработки

В двух терминалах запустите API и Vite:

```bash
pip install -r server/requirements.txt
# Задайте ADMIN_PASSWORD, SESSION_SECRET (не менее 32 символов) и DATA_DIR.
python -m uvicorn server.app:app --reload --host 127.0.0.1 --port 8000
```

```bash
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite. Его `/api/` проксируется на локальный сервер. Для локального импорта YouTube установите ffmpeg и Node.js 22 в `PATH`; контейнер API уже содержит оба инструмента. `npm run build` собирает веб-интерфейс в `dist/`; для общей медиатеки рядом с ним нужен API.

## Docker Compose

Скопируйте `.env.example` в `.env`, затем задайте длинный уникальный пароль администратора и случайный `SESSION_SECRET` длиной не менее 32 символов.

```bash
docker compose up --build -d
```

Контейнер `web` отдаёт сайт на внутреннем порту 8080 и перенаправляет `/api/` контейнеру `api` на внутреннем порту 8000. В `compose.yaml` используются только `expose`: порты на хосте не публикуются, а API доступен только в отдельной сети между контейнерами приложения. Для доступа извне подключите существующий обратный прокси к сети `dr-stun_default` и направьте домен на `http://dr-stun-web:8080`. Например, для уже запущенного контейнера прокси:

```bash
docker network connect dr-stun_default <reverse-proxy-container>
```

Используйте HTTPS на внешнем прокси. Админка доступна по `/admin.html`; публичная библиотека — по `/p/all`, плейлист артиста — по ссылке `/p/<artist-slug>`. SQLite и импортированные аудиофайлы остаются в именованном томе `dr-stun_library_data` при пересборке и перезапуске контейнеров. Проверки состояния: `/healthz` для веб-сервера и `/api/healthz` для API.

Администратор может загрузить MP3/MP4 или добавить YouTube-ссылку (до 150 МБ и 20 минут на трек). Импорт использует yt-dlp, ffmpeg и локальный JavaScript-движок Node.js 22; результат хранится как аудио в томе. Для YouTube-импорта используйте материалы, на которые есть права или разрешение; доступность импорта зависит от правил площадки. Пользовательские файлы, загруженные в сам визуализатор, продолжают проигрываться локально в браузере.

Для карточек соцсетей задайте публичный HTTPS-адрес в `VITE_SITE_URL` внутри `.env` перед сборкой. Без Docker задайте ту же переменную перед `npm run build`.

## Управление

- **Запустить переживание** включает клип и звук. Браузер требует пользовательского действия перед воспроизведением со звуком.
- **Загрузить клип** или перетаскивание файла на сцену принимает локальное видео либо аудио. Файл остаётся на устройстве пользователя.
- **Радио**: `/p/all` включает все треки, `/p/<artist-slug>` — только треки артиста. В радиорежиме значок загрузки становится кнопкой следующего трека; муха иногда переключает музыку сама, но выдерживает минимум около 85 секунд между переключениями. Небольшой блок показывает её любимые и нелюбимые треки.
- **Ночной клуб / Оранжерея / Дом** переключают оформление пространства без остановки клипа.
- Мышь или касание вращает ракурс; колесо меняет масштаб. Пробел ставит на паузу.
- **D** или маленький значок звуковой волны вверху открывает панель отладки: живые характеристики звука, текущий танцевальный рисунок и амплитуды движений с их звуковыми причинами. Панель скрыта по умолчанию; для автоматического открытия добавьте `?debug=1` к адресу.
- **Записать сцену** на телефоне в портрете создаёт видео 9:16 (1080×1920, до 30 кадров/с) со звуком и нейрокартой, без интерфейса. После записи можно открыть системное меню «Поделиться» или скачать файл. На больших экранах запись сохраняет размер окна и до 60 кадров/с. При поддержке браузера используется MP4 (H.264/AAC), иначе WebM. Поворот телефона завершает запись и сохраняет файл.

Экран телевизора, аудиоанализ и дорожка записи берутся из одного `HTMLVideoElement`. Не используется отдельное воспроизведение, которое могло бы разойтись с изображением. Нейрокарта — визуальная симуляция, не научная модель мозга.

## 3D-модель мухи

В текущей сборке муха процедурная: так она сразу доступна без внешних запросов, а крылья и поза анимируются под музыку. Для замены найден качественный [Fly – Low Poly от Leomaderart](https://sketchfab.com/3d-models/fly-low-poly-bc214680306e460d8ec72db056d76858), около 2,9 тыс. треугольников, лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) с обязательной атрибуцией. Это выразительная обычная муха, не точная дрозофила. Вариант без требования атрибуции — [Fly от Kohyzazi](https://poly.pizza/m/kCLW4c0kGx), около 1,1 тыс. треугольников, [CC0](https://creativecommons.org/publicdomain/zero/1.0/), но заметно проще по форме.

Референс [fly24-public](https://github.com/georgesher/fly24-public) также строит муху процедурно; визуальная модель и музыкальная библиотека здесь реализованы отдельно.
